# LeafBlog 博客写作指南（通用 AI 适用规范 v2.1）

> **说明**：本文件是 LeafBlog（基于 Cloudflare Workers + KV 的个人技术博客，域名 `leafblog.ccwu.cc`）内容生产的唯一规范准绳，适用于任何 AI 助手（Claude、ChatGPT、Gemini、Codex、Qoder 等）。  
> **调用方式**：写博客前把本文件喂给 AI，或直接输入指令：`「按照 blog-content/BLOG-WRITING-GUIDE.md 的规范写一篇关于 xxx 的博客」`。

---

## 一、工作流程（Standard Workflow）

```markdown
- [ ] 1. 资料调研与事实核查：定位权威一手信源，交叉验证核心数据、发布日期与技术事实
- [ ] 2. 封面图检索与准备：优先联网检索权威官方/真机无水印大图；若生成必须有真实参考
- [ ] 3. 创建目录与资源收容：创建 blog-content/<slug>/，封面统一保存为 cover.png
- [ ] 4. 正文撰写：按文章类型套用专属结构模板，撰写 blog-content/<slug>/article.md
- [ ] 5. 质量自查：对照六维自检清单严格校验（真实性、封面合规、排版、代码、行数、元数据）
- [ ] 6. 交付发布信息：输出 GitHub raw 封面链接、永久链接、标题、标签与后台录入步骤
```

## 二、资讯真实性与事实核查纪律（Fact-Checking & Authenticity）

技术资讯与发布解读类文章**严禁凭空编造事实或拼凑幻觉**。AI 在检索与写作时必须严格执行以下纪律：

### 1. 信源金字塔（Source Hierarchy）

| 级别 | 信源类型 | 适用场景 | 权威度要求 |
| --- | --- | --- | --- |
| **T1（一手核心源）** | 官方发布博客、官网 Newsroom、GitHub 官方仓库（Releases/Commits/README）、Model Card、官方白皮书、官方直播/发布会记录 | 事实认定基准 | **最高**。所有版本号、跑分基准、硬件参数、价格、API 规范必须以此为准 |
| **T2（权威专业源）** | arXiv 预印本、顶级学术会议、Ars Technica、The Verge、Bloomberg、The Information、MacRumors 等主流深度媒体与知名分析师报道 | 架构解读与产业背景 | **高**。可作为深度机制补充或供应链参考，需注明来源 |
| **T3（社区与传闻源）** | X（Twitter）技术圈爆料、Reddit 论坛讨论、LMSYS 竞技场盲测、供应链传闻 | 前瞻爆料与社区反响 | **参考**。**必须严格标注为「传闻/供应链预测」**，严禁作为确定事实陈述 |

### 2. 交叉验证与数据求证原则
- **跑分与参数（Specs & Benchmarks）**：严禁自行臆造模型跑分或芯片数据。引述基准时必须注明具体评估版本及测试环境，优先采纳官方公布数据；
- **发布时间与时效窗口**：文章必须明确注明**基准时间锚点**（如「2026 年 9 月正式发布」或「截至 2026 年秋季」），避免读者阅读时因时间错位产生误解；
- **价格与计费规则**：必须区分**首发定价**与**教育优惠/限时规则**，并明确标注货币单位（人民币 ￥ 或美元 $）。

### 3. 事实与观点的语义隔离规范
- **官方已确认事实**：使用确凿陈述，如「苹果于 2026 年 9 月 9 日特别活动中正式发布搭载 A20 Pro 的 iPhone 18 Pro……」；
- **社区爆料与未证实信息**：必须使用审慎限定词，如「据科技媒体与供应链消息披露……」、「目前该折叠形态处于传闻阶段，尚未获官方正式确认……」；
- **观点与分析**：明确为主观研判，如「从半导体能效比与工业设计角度来看……」、「结合其产品线分化策略推测……」。

## 三、封面图获取与制作规范（Search First & Grounded Generation）

封面图必须采用 **16:9 宽幅**（如 `2048x1152`、`1920x1080` 或 `1792x1024`），统一保存在 `blog-content/<slug>/cover.png`。

### 1. 第一原则：网络检索真实素材优先（Search First）
- **严禁未经检索便随意自行生图**。对于科技硬件发布会、大模型新版本发布、开源软件等，必须优先在网络上查阅真实素材；
- **优质检索渠道**：
  - 官方新闻中心与图库：如 Apple Newsroom、Google Blog / DeepMind Press Assets、GitHub 官方发布仓库等；
  - 官方活动海报与 Keynote 宣传图：如苹果发布会官方 Invite / Event Banner、WWDC 主视觉等；
  - 权威科技媒体实拍图与公开免版税图库（Unsplash / Pexels 等）。
- **下载与格式要求**：找到高清原图后下载，若为 `.jpg`、`.jpeg` 或 `.webp`，统一转为标准 `.png` 格式落盘至 `blog-content/<slug>/cover.png`。

### 2. 第二原则：AI 生成必须有真实参考（Grounded Generation Only）
- 只有在网上**确实无法检索到清晰、无版权风险或比例适配的现成图片**时，才允许使用 AI 绘图工具生成；
- **必须有据参考，严禁随意盲目生成**：
  - 提示词必须严格基于**真实产品设计规格与官方设计语言**（例如：具体的真实配色命名、机身材质如航空钛/超瓷晶、真实摄像头模组排列、真实可变光圈结构、微边框视觉等），或者提供官方真机参考图进行图生图（Image-to-Image）；
  - **绝对严禁脱离现实随意生成四不像、乱七八糟的架空臆造图**；
  - 提示词必须显式声明负向提示：`no text, no letters, no words, no watermark, no logo`，确保画面干净纯粹；
  - 风格保持现代极简科技风（Modern Minimalist Tech Banner），色彩质感沉稳高级。

## 五、排版细节与表现力规范

- **中英文混排**：中英文之间保持自然空格；技术专有名词保留官方大小写（如 `iPhone 18 Pro`、`A20 Pro`、`Apple Intelligence`、`Cloudflare Workers`）。
- **标点符号**：正文使用中文全角标点；英文专有名词与行内代码使用半角符号；并列短语统一使用中文顿号（、）；强调用「」包裹。
- **重点突出**：每小节的关键结论、核心参数、关键亮点使用 `**加粗**` 呈现，杜绝整段泛滥加粗。
- **引用块与金句**：官方原话、设计哲学或关键结论使用 `>` 引用块：
  > 「引用核心金句或重要提示。」
- **代码与配置规范**：必须显式标注语言标识符（如 `bash`、`python`、`yaml`、`json`、`text`），代码具备直接可读性，关键参数附带行内注释。
- **横评表格规范**：涉及 3 项及以上的参数并列（如机型对比、参数明细）必须使用 Markdown 表格，提升信息密度。
- **篇幅控制**：正文控制在 **120 ~ 180 行 Markdown**（不含顶部注释块），信息密度优先，杜绝大段无意义废话与水分。

## 六、目录结构与发布注释块

### 1. 目录收容规范

```text
blog-content/
└── <slug>/          # 永久链接命名：小写英文单词 + 连字符短横线（如 apple-fall-event-summary）
    ├── article.md   # 正文 Markdown 文件（顶部含发布注释块）
    └── cover.png    # 16:9 真实/有据参考封面图片
```

> **注意**：`blog-content/` 目录位于仓库根目录内，仅用于静态资产管理与版本控制。封面图片通过 GitHub Raw 链接直接供给前端页面加载，**在博客后台发布文章前，必须先将该文件夹 push 至远程 GitHub 仓库**。

### 2. 发布指引注释块模板

`article.md` 最上方必须放置以下注释块（作者录入后台时手动删除）：

```markdown
<!--
============================================================
发布指引（发布时删除本注释块）
后台入口: https://leafblog.ccwu.cc/admin → 新建文章
- 标题:     <符合规范的吸引力标题>
- 特色图片: https://raw.githubusercontent.com/Fallenleaf-hub/My-blog-theme/refs/heads/main/blog-content/<slug>/cover.png
- 永久链接: <slug>
- 分类:     按后台分类选择（如：硬件芯片、人工智能、前端开发等）

============================================================

```

> 💡 **极速自动发布（GitOps 自动化流）**：  
> 当你在 GitHub 仓库中配置了 `BLOG_USER` 与 `BLOG_PASSWORD` 密钥后，每次完成写作并执行 `git push` 推送到 `main` 分支，GitHub Actions 将**自动解析本文档元数据并同步发布到博客**，自动分配 ID、增量更新并刷新 CDN 缓存，无需再手动进入后台复制粘贴！

## 七、文章发布前自检清单（Pre-Flight Checklist）

在交付给作者之前，AI 必须对照以下六项逐一自检：

1. **[ ] 事实真实性核验**：
   - 核心参数、发布日期、芯片架构、跑分指标均有权威一手/专业信源佐证；
   - 传闻爆料与官方事实已从句式上做严格限定区分；
   - 包含明确的基准时间锚点（如 2026 年秋季发布会）。
2. **[ ] 封面图合规**：
   - 封面优先采用网络检索的官方/真实高分辨率无水印素材；
   - 若由 AI 生成，必须有官方真机工业设计/参数实物作为直接参考，严禁盲目凭空生成；
   - 比例为 16:9，画面无文字、无乱码水印。
3. **[ ] 篇幅与信息密度**：
   - 行数处于 120 ~ 180 行区间，逻辑紧凑，信噪比高。
4. **[ ] 格式与排版规范**：
   - 标点规范，中英文空格自然，技术名词大小写准确；
   - 包含多列对比表格，数据详实。
5. **[ ] 结构完整性**：
   - 符合所选模板的逻辑层级，文末附带权威参考链接。
6. **[ ] 交付清单齐全**：
   - 正文已写入 `blog-content/<slug>/article.md`；
   - 封面图片已保存至 `blog-content/<slug>/cover.png`；
   - 提交后只需 `git push`，流水线将全自动完成同步与全网发布。
