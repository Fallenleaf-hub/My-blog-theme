# LeafBlog 博客写作指南（通用 AI 适用）

> 本文件是博客内容生产的唯一规范来源，适用于任何 AI 助手（ChatGPT、Claude、Codex、Gemini、Qoder 等）。
> 用法：写博客前把本文件内容喂给 AI，或直接说「按照 blog-content/BLOG-WRITING-GUIDE.md 的规范写一篇 xxx 的博客」。

为 LeafBlog（Cloudflare Workers + KV 个人博客，域名 `leafblog.ccwu.cc`）生成风格统一的博客内容。每篇文章产出一个独立文件夹，包含正文与封面图，并给出发布所需的全部字段。

## 工作流程

```
- [ ] 1. 资料调研：联网搜索并抓取权威信息（官方仓库 README、官方文档优先）
- [ ] 2. 生成封面图：AI 绘图，16:9 宽幅
- [ ] 3. 创建目录：blog-content/<slug>/，封面保存为 cover.png
- [ ] 4. 撰写正文：blog-content/<slug>/article.md
- [ ] 5. 交付发布信息：特色图片 URL、永久链接、标题、标签、发布步骤
```

### 1. 资料调研

- 优先定位官方来源（GitHub 仓库、官网、官方文档），抓取原文而非二手转述
- 技术类文章必须覆盖：是什么、安装/快速开始、核心用法、架构或原理亮点、注意事项
- 事实性内容（版本号、Star 数、命令、配置项）必须来自调研结果，不得虚构；无法核实的信息要标注

### 2. 封面图

用 AI 绘图工具生成（1792x1024 或同比例 16:9），prompt 要求：

- 现代极简科技风横幅（tech blog cover banner），与文章主题意象相关
- 深色渐变背景 + 柔和光效，flat illustration 风格
- 明确声明 `no text, no letters, no words, no watermark`

生成后保存为 `blog-content/<slug>/cover.png`。

### 3. 目录规范

```text
blog-content/
└── <slug>/          # 以文章永久链接命名（小写英文 + 连字符）
    ├── article.md   # 正文，顶部含发布信息注释块
    └── cover.png    # 封面图
```

`blog-content/` 仅用于内容管理，不参与博客部署。封面通过 GitHub raw 链接引用，**发布前必须先把该文件夹 push 到 GitHub**。

## 发布信息注释块

article.md 顶部固定格式（发布时由作者删除）：

```markdown
<!--
============================================================
发布指引（发布时删除本注释块）
后台入口: https://leafblog.ccwu.cc/admin → 新建文章
- 标题:     <文章标题>
- 特色图片: https://raw.githubusercontent.com/Fallenleaf-hub/My-blog-theme/refs/heads/main/blog-content/<slug>/cover.png
- 永久链接: <slug>
- 分类:     按后台分类选择
- 标签:     <3~5 个，英文逗号分隔>
发布后记得点击后台「发布」按钮清理 Edge Cache
============================================================
-->
```

## 正文结构模板

```markdown
# <标题>

<开篇 2~3 段：是什么、为什么值得关注，加粗关键概念，以一句点睛的总结收尾>

![<主题> 封面](<封面 raw URL>)

## 一、<是什么 / 背景>
## 二、<快速开始 / 安装>          # 含代码块
## 三、<核心用法 / 首次运行>        # 分步说明
## 四、<原理 / 架构亮点>            # 可选，可用表格
## 五、<进阶玩法>                  # 可选，简短列表
## 六、<注意事项与展望>            # 编号列表 + 收尾段
## 参考链接                        # 官方来源列表
```

## 写作风格规范

- **语言**：中文正文，技术名词保留英文原文（如 Harness、API Key、slug）
- **标点**：中文全角标点；引用强调用「」；并列用顿号
- **加粗**：每节的关键结论、命令入口、重要警告用 `**加粗**`，不滥用
- **代码块**：命令与配置必须标注语言（bash/yaml/toml 等），可直接复制执行
- **表格**：3 列以上的并列信息（包/职责、配置项/说明）优先用表格
- **小节引用**：官方金句或重要提示用 `>` 引用块
- **链接**：行内链接指向官方来源；文末集中列参考链接
- **篇幅**：正文 120~180 行 Markdown，信息密度优先，不注水
- **语气**：平实专业，有观点但不夸张；结尾段给出简短展望或评价

## 交付清单

完成后向作者交付：

1. 文章文件路径 `blog-content/<slug>/article.md`
2. **特色图片 URL**（GitHub raw 格式，见注释块模板）
3. **永久链接**（slug），说明发布后的文章地址格式 `/article/{id}/<slug>.html`
4. 建议标题与标签
5. 发布步骤提醒：push 仓库 → /admin 新建文章 → 填字段粘贴正文 → 点「发布」清缓存
